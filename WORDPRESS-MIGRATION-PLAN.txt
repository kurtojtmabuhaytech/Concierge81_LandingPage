 1. STATIC VS DYNAMIC
================================================================================

  Part                                Mode     Edited where
  ----------------------------------  -------  ----------------------------------
  Landing page (14 sections)          STATIC   Theme code (front-page.php +
                                               template-parts/landing/*)
  Header (logo, nav, CTA)             STATIC*  header.php (*nav links can come
                                               from Appearance > Menus)
  Contact section + lead form         STATIC   template-parts/contact.php
  Footer                              STATIC*  footer.php (*links via a menu)
  Blog listing                        DYNAMIC  Posts in wp-admin
  Blog article                        DYNAMIC  Posts in wp-admin (block editor)
  Newsroom listing                    DYNAMIC  "News" post type in wp-admin
  News announcement                   DYNAMIC  "News" post type in wp-admin
  Featured story (blog / news)        DYNAMIC  "Featured" checkbox on a post
  Categories / filters                DYNAMIC  Posts > Categories, News > Categories
  "Keep reading" / "More from news"   DYNAMIC  Automatic (latest / same category)
  Contact email, press email          OPTION   Settings > Concierge81 (one place)

  Unchanged: the design, SCSS architecture, Design System V2 tokens,
  main.js behaviour, scroll-reveal animation, images and responsive rules.

 2. ARCHITECTURE OVERVIEW
================================================================================

   ┌──────────── this repo (git) ────────────┐        ┌──── Local WP ────┐
   │ index.html … news-article.html (design  │        │ concierge81.local │
   │   reference; kept)                      │        │                   │
   │ assets/scss  (single source of styles)  │──sass──┐│                   │
   │ assets/js/main.js                       │        ││                   │
   │ wordpress-theme/concierge81/  (THEME)   │◄───────┘│                   │
   │   PHP templates, inc/, template-parts/  │ sync ──►│ wp-content/themes/│
   │ scripts/ (build, sync, import, qa)      │         │   concierge81/    │
   └─────────────────────────────────────────┘         └───────────────────┘

  - A classic PHP theme. No page builder; no plugin is required to render.
  - Styles: the same SCSS compiles to wordpress-theme/concierge81/assets/css/
    theme.css, so the static prototype and the theme never drift apart.
  - Content for dynamic parts comes from WP_Query; markup comes from the same
    template parts, so the server render and "Load more" render are identical.
  - Custom code lives in the theme (inc/*.php). Data definitions (post type,
    meta) are in a small "functionality" section of the theme for now, and can
    move to a must-use plugin later so content survives a theme switch
    (see decision D5).

 6. HOW EACH DYNAMIC FEATURE WORKS
================================================================================

  Featured story     WP_Query: newest post with c81_featured = 1 (blog / news).
                     If none, the newest post. It's excluded from the list below.
  Card list          First page from WP_Query (6 blog / 8 news), rendered by
                     template-parts/blog/card.php or news/row.php.
  Load more          main.js calls GET /wp-json/c81/v1/cards?type=post|news
                     &cat=<slug>&page=N. The endpoint runs WP_Query and returns
                     { html, hasMore, total } built with the SAME template part,
                     so new cards look identical. The button hides when
                     hasMore is false.
  Filters            Pills are category links (/blog/category/guides/), so they
                     work without JS and are SEO-friendly. With JS they fetch
                     page 1 for that category through the same endpoint without
                     a reload, and update the URL with history.pushState.
  Empty state        Shown when a category returns 0 items.
  Reading time       c81_reading_time(): word count of post_content / 220,
                     rounded up, min 1.
  On this page       toc.php filters the_content: gives every <h2> an id (slug
                     of its text) and returns a list for template-parts/blog/
                     toc.php. The JS highlight already exists in main.js.
  Keep reading       3 latest posts in the same category (fallback: latest),
                     excluding the current post.
  More from news     3 latest news items excluding the current one.
  Share / Copy link  Unchanged JS; URL comes from the permalink.
  SEO basics         Title tag via add_theme_support('title-tag'); the excerpt
                     becomes the meta description; Open Graph image = featured
                     image (or an SEO plugin later, decision D4).

 8. BUILD AND SYNC WORKFLOW
================================================================================

  scripts/build.ps1
    1. sass assets/scss/theme.scss -> wordpress-theme/concierge81/assets/css/theme.css
       (theme.scss = landing.scss + WP-only partials such as alignments and
        editor helpers)
    2. sass assets/scss/editor.scss -> .../assets/css/editor.css
    3. copy assets/js/main.js and assets/images -> theme assets

  scripts/sync-theme.ps1
    robocopy wordpress-theme\concierge81 -> Local Sites\concierge81\app\public\
    wp-content\themes\concierge81  (/MIR, excludes .git and node_modules)

  Day-to-day: edit in the repo -> run build + sync (one command:
  scripts/dev.ps1) -> refresh concierge81.local. Optionally a file watcher
  re-syncs on save.
  Enqueued file versions use filemtime(), so the browser never shows stale CSS.

 9. WP-CLI SETUP AND CONTENT IMPORT
================================================================================

  WP-CLI ships with Local:
    ...\Local\resources\extraResources\bin\wp-cli\wp-cli.phar
  and runs with Local's PHP 8.2 against the running site database. If Local's
  MySQL socket/port needs it, commands run from Local's "Open site shell"
  environment (script: scripts/wp.ps1 wraps this).

  Setup commands (scripts/setup-site.ps1):
    wp theme activate concierge81
    wp rewrite structure '/blog/%postname%/' --hard
    wp post create --post_type=page --post_title=Home    --post_status=publish
    wp post create --post_type=page --post_title=Blog    --post_status=publish
    wp option update show_on_front page
    wp option update page_on_front <Home id>
    wp option update page_for_posts <Blog id>
    wp term create category "Guides" ... (all blog categories)
    wp term create news_category "Product" ... (+ badge term meta)
    wp menu create primary / footer / legal; wp menu item add-custom ...
    wp menu location assign primary primary  (etc.)
    wp option update c81_contact_email info@mabuhaytech.com

  Content import (scripts/import-content.php, run with wp eval-file):
    - 12 blog posts and 12 news items from the static pages (title, excerpt,
      category, date, eyebrow suffix, featured flag on the featured ones)
    - The full Figma article body for "How AI concierges cut front-desk wait
      times by half." and "Concierge81 launches Voice Mode for lobby kiosks."
      built from the editor patterns
    - Images imported to the Media Library with wp media import and set as
      featured images (header photos stay placeholders until supplied)
    - Author "Carlo Mendoza" (user) with c81_job_title

  Safety: before any import, take an UpdraftPlus / wp db export backup.
  The import script is idempotent: it skips items that already exist by slug.

 11. QUALITY ASSURANCE PLAN
================================================================================

  Tool: Playwright (Microsoft's browser-automation test runner), driving
  the Microsoft Edge already installed. Added to the repo as a dev
  dependency (package.json + tests/), so the same tests run against the
  static files now and against concierge81.local later.

  Test suites
  -----------
  1. Smoke         Every page loads: HTTP 200, no console errors, no failed
                   requests (missing CSS/JS/images/fonts).
  2. Links/assets  Every internal link and image resolves (no 404s); anchors
                   (#contact, #faq ...) exist on the page.
  3. Responsive    Widths 320, 390, 768, 1024, 1440, 1920: no horizontal
                   scroll (except the industry gallery); header and hamburger
                   swap correctly; full-page screenshot per width.
  4. Interaction   Hamburger opens and closes (outside tap, Escape, link) and
                   scroll stays locked; FAQ filters; blog/news filters + Load
                   more counts; gallery arrows and dots; inbox drag; copy
                   buttons; Share fallback; "On this page" highlight; contact
                   form validation.
  5. Animation     Reveal elements become visible when scrolled into view and
                   fade out when they leave; reduced-motion shows everything
                   immediately.
  6. Accessibility axe-core scan on every page (WCAG 2.1 AA): contrast, labels,
                   heading order, landmarks, alt text, button names.
  7. Visual        Screenshot baselines; later the WordPress pages are compared
     regression    pixel-by-pixel with the static ones (phase 1-3 acceptance).
  8. Performance   Lighthouse (Edge) on each page: performance, accessibility,
                   best practices, SEO scores + largest files.

  Output
  ------
  - An HTML report (npx playwright show-report): pass/fail per test, with
    screenshots, video and a step-by-step trace for every failure.
  - A summary in chat with each finding and the proposed fix.

  Watching it run live (see the chat reply for the steps)
  ------------------------
  - Headed mode: a real Edge window opens on your screen and you watch the
    pages scroll, menus open and filters click in real time (slowed down).
  - UI mode: Playwright's own window with a live list of tests, a timeline,
    and a DOM snapshot for every step. You can re-run any test yourself.

 12. RISKS AND HANDLING
================================================================================

  Risk                                         Handling
  -------------------------------------------  ---------------------------------
  Static and WP styles drift apart             One SCSS source builds both
  Editor content breaks the article layout     Patterns + block styles + theme.json
                                               palette; editor.css preview
  Load-more cards differ from server cards     Same template part renders both
  Theme switch loses News content              Post type can move to a mu-plugin (D5)
  Local DB connection for WP-CLI               Run through Local's site shell
                                               environment (scripts/wp.ps1)
  Large images slow the site                   WP image sizes + srcset; compress
                                               Avatar.png
  Import duplicates                            Idempotent import keyed by slug;
                                               backup first
  Writing outside the repo (Local Sites)       Only via sync script; you approve
                                               the permission prompts
